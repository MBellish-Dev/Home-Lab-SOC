Investigation 001 — Nmap Reconnaissance

Objective
- Determine whether an Nmap network reconnaissance scan originating from the Kali Linux VM can be detected and investigated using the current Wazuh deployment.

Environment

  System                    Role
Kali Linux         Security testing / reconnaissance
Windows 11         Target endpoint
Ubuntu Server      Wazuh Docker host
Wazuh              SIEM / security monitoring

Scenario
- An automated Nmap scan was configured on the Kali Linux VM to perform controlled network reconnaissance against the Windows 11 endpoint.
- The activity was performed within the home lab.
- The objective is to determine what evidence of the reconnaissance activity is visible through the current security monitoring configuration.

Investigation Questions
 1. Does Wazuh receive telemetry associated with the scan?
 2. Does Windows generate events corresponding to the scan?
 3. Does Wazuh generate an alert?
 4. Can the source system be identified?
 5. Can the target ports or connections be identified?
 6. Is the available telemetry sufficient to identify network reconnaissance?
 7. If detection is unsuccessful, what telemetry is missing?

Investigation
 - Step 1 — Establish Scan Timestamp
     - Record the exact time the scan begins and ends.
 - Step 2 — Review Wazuh
     - Review events generated by the Windows 11 Wazuh agent around the time of the scan.
- Step 3 — Identify Relevant Telemetry
     - Determine whether available events provide information about:
       - Source
       - Destination
       - Port
       - Protocol
       - Connection attempts
       - Firewall activity
       - Other indicators of reconnaissance
 - Step 4 — Determine Detection
     - Determine whether Wazuh:
       - Generated an alert
       - Recorded relevant events without generating an alert
       - Recorded insufficient information
       - Recorded no useful evidence
